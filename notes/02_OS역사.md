# 2강 — OS의 역사와 핵심 개념

## 흐름
배치 → 스풀링 → 멀티프로그래밍 → 타임 셰어링

| 단계 | 핵심 | 한계 |
|---|---|---|
| 배치 | 순서대로 하나씩 | I/O 동안 CPU idle |
| 스풀링 | I/O를 버퍼에 맡기고 계속 연산 | 동기 I/O에는 불가 |
| 멀티프로그래밍 | 메모리에 2개 이상, I/O 시 교체 | 공평성 문제 |
| 타임 셰어링 | 타임 슬라이스마다 선점 | 컨텍스트 스위치 오버헤드 |

## 기억할 것
- 컨텍스트 스위치 = 현재 프로그램의 PC·레지스터 저장 → 다음 프로그램 것 복원
- 타임 슬라이스↓ → 공평성·응답성↑ / 오버헤드↑ (트레이드오프)
- Concurrency ≠ Parallelism
